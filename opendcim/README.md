# OpenDCIM – iDT4GDC

This directory contains the **OpenDCIM deployment** used within the iDT4GDC digital-twin platform.
It provides an asset-centric digital twin of data-centre infrastructure and integrates with Keycloak for authentication.

The deployment is fully containerised using **Docker Compose** and includes:
- **OpenDCIM 23.04** — web application for infrastructure modelling
- **MariaDB 10.11** — configuration database
- **Nginx** — HTTPS reverse proxy
- **Keycloak 26.0** — OIDC identity provider

---

## Prerequisites

- Docker and Docker Compose v2
- `openssl` (for certificate generation)
- Environment variables from the root `.env` file — source it before running scripts:
  ```bash
  source ../.env
  ```

## Service ports

| Port | Service | Description |
|---|---|---|
| `443` | OpenDCIM (HTTPS) | Main web UI, accessed via Nginx reverse proxy |
| `80` | Nginx (HTTP) | Redirects to HTTPS |
| `8080` | Keycloak | OIDC identity provider admin console and token endpoints |

## Environment variables

The setup scripts read the following variables, with the defaults shown:

| Variable | Default | Description |
|---|---|---|
| `OIDC_ENDPOINT` | `http://keycloak:8080/realms/idt4gdc` | Keycloak realm URL (internal container network name) |
| `OIDC_USERID` | `test` | OpenDCIM OIDC user ID |
| `OIDC_CLIENT_ID` | `opendcim` | OIDC client ID registered in Keycloak |
| `OIDC_CLIENT_SECRET` | `CHANGE_ME` | OIDC client secret — set this after running `opendcim_init_oidc_params.sh` |
| `OPENDCIM_USERID` | `test` | OpenDCIM user account for API access |
| `OPENDCIM_APIKEY` | *(see `.env.example`)* | API key set by `opendcim_promote_site_admin.sh` |

## Step 1 – Generate TLS certificates

OpenDCIM is served over HTTPS. A self-signed certificate valid for 10 years is generated for `localhost`:

```bash
./scripts/opendcim_generate_nginx_certs.sh
```

This creates:
```
code/nginx/certs/localhost.crt
code/nginx/certs/localhost.key
```

The script is safe to re-run — it exits without overwriting if certificates already exist. To regenerate, delete both files first.

To add additional SANs (e.g. a hostname or extra IP):
```bash
SAN_DNS_EXTRA=myhost.local ./scripts/opendcim_generate_nginx_certs.sh
SAN_IP_EXTRA=192.168.1.10  ./scripts/opendcim_generate_nginx_certs.sh
```

---

## Step 2 – Start OpenDCIM

```bash
./scripts/opendcim_up.sh
```

Starts all four containers: MariaDB, OpenDCIM, Nginx, and Keycloak. Verify with:

```bash
docker ps
```

Wait until all containers report `healthy` or `running` before proceeding. Keycloak in particular takes ~30 seconds to be ready.

---

## Step 3 – Initialise OIDC configuration

Once all containers are up, write the OIDC parameters into OpenDCIM's database:

```bash
./scripts/opendcim_init_oidc_params.sh
```

This runs SQL against the MariaDB container to populate the `fac_Config` table with the Keycloak realm endpoint, client ID, client secret, and user ID. The script prints the resulting OIDC rows so you can verify the values are correct.

---

## Step 4 – Log in and promote the admin user

Navigate to `https://localhost` and log in with the test account:

```
Username: test
Password: password
```

This first login registers the user in OpenDCIM via the OIDC flow. Then run:

```bash
./scripts/opendcim_promote_site_admin.sh
```

This grants the `test` user full Site Administrator privileges (SiteAdmin, ReadAccess, WriteAccess, DeleteAccess, BulkOperations) and sets its API key to the value of `OPENDCIM_APIKEY`. The API key is used by the DT Bridge to post PDU statistics.

---

## Step 5 – Import reference data

Reference infrastructure data is provided in `data/`. Follow the import instructions in:

```
opendcim/data/README.md
```

This establishes a minimal but realistic OpenDCIM model for iDT4GDC experiments, including containers, cabinets, device templates, and devices. PDUs must be created manually after import.

---

## Stopping OpenDCIM

```bash
./scripts/opendcim_down.sh
```

This stops and removes all containers without deleting the MariaDB data volume, so data persists across restarts.
